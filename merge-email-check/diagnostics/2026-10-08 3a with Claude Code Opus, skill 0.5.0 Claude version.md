The places where the instructions were unclear, or where we had to guess:

1. **Placeholders in comments.** "Changing only its placeholders ... every copy of each" reads as mandatory, while "replacing those as well does no harm" reads as optional. We replaced the comment copies in script 00 and the first script 03 run, but left them in scripts 01, 02 and the second script 03 run. No harm either way.
2. **Email names.** Nothing says whether to tidy a broken name from script 00 (above).
3. **Screenshot scale.** `get_screenshot` returns 1x at best, and the long Faults A frames came back at about 0.79x and 0.9x even with `maxDimension` 4096. Small footer text was barely readable. The skill doesn't mention that the tool returns a URL to download rather than an inline image.
4. **Per-email counts.** Script 02's `counts` are summed over the whole scope, but the scorecard is per email, so we recounted EM-06, EM-07, EM-11, EM-12, EM-29 and EM-30 from each frame's `images` rows. `em17.families` is also scope-wide, so we had to infer which email uses which font from the layer counts (Playfair Display 8 + Inter 30 = Faults A's 38 text layers; Arial 32 = B, C and D).
5. **EM-03 with a suggestion-only note.** Faults A has 11 modules: 5 noted, 1 with only a suggestion, 5 with none. If the suggestion counts as a problem, that's 6 of 11 and Fail; if only the 5 with no note count, it's Partly. We used `noted` against `modules` as written, which gives Fail.
6. **EM-15 beyond zero.** The rule gives only "Pass when `count` is 0". We used Fail for any pure background, not the default rule, because the rule gives no group to count against.
7. **An empty desktop frame (Faults C).** We judged EM-02, EM-04 and EM-05 N/A, since the empty frame counts as missing under EM-01. EM-02 could also be read as Pass, because the mobile frame does sit to the left.
8. **EM-09 when the only image is the logo** (B, C, D). We used N/A. Pass is also defensible.
9. **EM-16 and the illustration's gray plate.** Script 02 lists 6:30 as an illustration, with `#f5f5f5` only on its holding layer 6:29. The node screenshot shows a light gray box, and we couldn't tell whether that gray is baked into the PNG. We judged the navy shapes against the dark reference as the skill says, which gives Fail.
10. **Where corrections go.** Step 3 says to "say in the report which you corrected", but step 7 says "use only the template's sections, adding none". We put the corrections in the opening paragraph and the Evidence column.
11. **EM-27 attribution.** Faults A's `em27` included a request note on 7:25, which belongs to the removed mail-app copy and was matched by name. It made no difference, since both entries were requests.
12. **EM-31 and the 15-image cap.** Most of Faults A's images were seen clearly in the frame screenshots rather than in their own. We counted those as seen, as EM-09 allows.
13. **The date.** The run crossed midnight. The report uses 2026-10-09, which was "today" when it was written.
14. **Separate from the skill:** in this environment, `grep` on a file under `/tmp` was blocked by a deny rule, so we pasted each filled script into `use_figma` by hand instead of filling it with `sed`.

The design was never written to. Every script was run as written, with only its placeholders changed, and we wrote no code of our own for Figma.
